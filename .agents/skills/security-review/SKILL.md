# Security review

[AGENTS.md](../../../AGENTS.md) owns verification and human review requirements.
Read the trust boundaries and rules relevant to the change; this skill adds
review criteria for those boundaries. Linked guides own detailed protocols.

## Trust boundaries in this repo

- **GitHub Releases to the installed app.** `pogled_assist/release_update.py` and
  `update_windows.ps1` accept only official stable releases of
  `Hasan-Smajlovic/Pogled-Assist` and their exact ZIP and `.sha256`
  assets. Settings pins the selected version, including an older stable release;
  the manual updater defaults to the latest stable release. Installation requests
  Administrator access. The
  [release guide](../../../docs/WINDOWS_RELEASE.md#update-an-installed-release)
  owns the selection, verification, cancellation, and installation protocol.
- **Typed messages to speech engines.** `pogled_assist/speech/speech_service.py` passes
  the message to eSpeak NG, `edge-playback`, in-process `edge_tts`, or ElevenLabs HTTPS.
  eSpeak NG stays offline. Prirodni sends text to Microsoft; Efendija sends it to
  ElevenLabs. Credentials and private saved clips follow the
  [storage contract](../../../docs/ARCHITECTURE.md#persistent-data-and-logs).
- **Machine environment to executables.** `TOBII_STREAM_ENGINE_DLL`,
  `POGLED_ASSIST_X86_PYTHON`, `ESPEAK_NG_EXE`, `EDGE_PLAYBACK_EXE`, and
  `TOBII_CALIBRATION_COMMAND` choose what the app loads or runs. `ELEVENLABS_API_KEY`,
  `ELEVENLABS_VOICE_ID`, and `ELEVENLABS_MODEL_ID` override local speech configuration.
- **The x86 bridge process.** `pogled_assist/tracking/tobii_stream_engine_bridge_backend.py`
  parses JSON lines from the 32-bit bridge and discards invalid payloads.
- **The public repository.** Everything under `language/` and
  `tests/fixtures/speech_suggestions/` is published.

## Rules

- Log typed text only as the `<text>` placeholder, as
  `SpeechService._start_process` does. Personal learning keeps word counts in
  `data/speech_learning.json`, never message transcripts. The
  [diagnostic logging contract](../../../docs/ARCHITECTURE.md#diagnostic-logging)
  owns the limits for structured events and traces.
- Pass user text to processes as one list element with the shell off. The
  shell launch in `pogled_assist/tracking/tobii_calibration.py` is reserved for the
  operator-set `TOBII_CALIBRATION_COMMAND`.
- Verify before changing files: a checksum, metadata, or network failure
  leaves the installed app unchanged. For an explicit selection, match the
  requested version to the returned tag and package `VERSION`. In the Settings
  flow, keep cancellation and restart confirmation ahead of installation.
  Selected historical packages still use the currently installed transactional
  installer.
- Change the pinned release source in both places together:
  `RELEASE_API_URL` and `RELEASE_DOWNLOAD_ROOT` in `pogled_assist/release_update.py`,
  and `$OfficialReleaseApiUrl` and `$OfficialReleaseAssetRoot` in
  `update_windows.ps1`.
- Keep `C:\TobiiExec` rejected by `packaging/windows/install_windows.ps1` and
  `update_windows.ps1`.
- Keep `.github/workflows/ci.yml` on `pull_request` with `contents: read`.
  Only the release job in `.github/workflows/release.yml`, triggered by a push
  to `master`, gets `contents: write` for publishing. The manual preparation job
  in `.github/workflows/prepare-release.yml` gets `contents: write` and
  `pull-requests: write` only to create `release/v<version>` and a draft PR.
  Do not execute code merged from `development` while that job has a write token.
- `.github/workflows/ui-gallery.yml` runs from the trusted default-branch workflow
  revision. Its build job reads CI artifacts; only its deployment job gets
  `pages: write` and `id-token: write`, and only its comment job gets
  `pull-requests: write`. Never execute PR code or publish PR-supplied HTML from
  that workflow. Publish only checked PNG data and HTML generated by the trusted
  script, as described in
  [UI gallery publication](../../../docs/UI_GALLERY.md#permissions-and-trusted-artifacts).
- Commit only synthetic or project-authored text under `language/` and
  `tests/fixtures/`, following the source and evaluation rules in the
  [Bosnian language guide](../../../language/bs/README.md).
- `.github/workflows/sync-hotfix.yml` may write only a separate backport branch and
  draft PR after a trusted repository hotfix merges into master. Validate repository,
  merge state, base, source repository/ref and merge SHA before mutation. Never run
  checked-out code or hooks with that token, push protected branches, or auto-merge.
  [Hotfix process](../../../CONTRIBUTING.md#hotfix-process) owns recovery and review.

## Before merging

- Updater or installer change: `tests/release/test_release_updater.py` and
  `tests/release/test_windows_installer.py` pass without weakened assertions, including
  `test_checksum_mismatch_stops_before_installer_runs` and
  `test_legacy_install_root_is_never_modified`. For version selection, also cover
  the source validation in `tests/release/test_version_selection.py` and the
  confirmation and cancellation flows in `tests/ui/test_release_update_e2e.py`.
  The pull request records the manual checks from the release guide as run or Not run.
- Speech or logging change: no new `logger` call formats message text, phrase
  text, or suggestion input.
- Workflow change: write permissions remain limited to release preparation,
  release publication, isolated hotfix backports, and the separate gallery deployment
  and comment jobs.
  The gallery build and PR CI jobs stay read-only, no `pull_request_target` trigger
  is added, and `scripts/checks/check_github_actions.ps1` passes through the
  repository verification entry point. Hotfix backports also require
  `tests/release/test_sync_hotfix.py` and human review of the final workflow diff.
